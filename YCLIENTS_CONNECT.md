# Подключение YCLIENTS

Секреты хранятся в `.env.local` и переменных окружения хостинга. Их не нужно отправлять в переписку или добавлять в Git. Пароль от основного аккаунта не нужен.

1. `YCLIENTS_COMPANY_ID` — ID именно филиала SHERLOCK. ID формы онлайн-записи может отличаться от ID филиала.
2. `YCLIENTS_PARTNER_TOKEN` — API-ключ из «Настроек аккаунта» в [кабинете разработчика](https://yclients.ru/appstore/developers). Нужен для получения мастеров, рейтингов и методов онлайн-записи.
3. `YCLIENTS_USER_TOKEN` — пользовательский токен с доступом к филиалу и чтению отзывов. Существующий ключ перенесён в это поле после подтверждения его типа владельцем.
4. У нужных сотрудников должен быть включён показ рейтинга (`show_rating = 1`). Сайт показывает полученную от API оценку от 1 до 5. Нулевой `votes_count` не скрывает рейтинг: API филиала может возвращать положительную оценку и `comments_count` при нулевом числе голосов. Голоса подписываются «оценки», комментарии — «отзывы»; если оба счётчика пусты, отображается только источник YCLIENTS.

Для текстов отзывов пользователь из `YCLIENTS_USER_TOKEN` должен иметь доступ именно к филиалу `1024543`. В текущем интерфейсе путь настройки: «Настройки → Настройки записи → Сотрудники» → роль пользователя в колонке «Доступ» → «Права доступа» → блок «Раздел Обзор» → «Просматривать отзывы». Если право скрыто, раскройте дополнительные права выбранной роли. Удаление отзывов не требуется; отдельный доступ к «Сводке» не является правом просмотра отзывов. `dash_reviews_access` — техническое имя поля API, а не название пункта интерфейса. Мастера и их рейтинги запрашиваются только с партнёрским токеном; пользовательский токен добавляется только при чтении комментариев.

Инструкции текущего интерфейса: [роли и права доступа](https://support.yclients.ru/5-9-282--roli-sotrudnikov-i-nastrojka-prav-dostupa/), [права раздела «Обзор»](https://support.yclients.ru/5-9-10-302--prava-dostupa-k-razdelu-obzor/).

Проверка после заполнения:

```sh
npm run check:yclients
```

Команда выполняет только GET-запросы к официальному API, показывает HTTP-статус, ID мастеров и доступность рейтинга. Она не создаёт записи, не выводит токены или данные гостей. При 401 проверяйте тип и актуальность токенов; при 403 — доступ интеграции и пользователя к филиалу.

После изменения окружения перезапустите сервер. На хостинге задайте те же серверные переменные и пересоберите приложение. Мастера и рейтинги обновляются с интервалом кеширования до пяти минут. Число оценок (`votes_count`) и число письменных отзывов (`comments_count`) не взаимозаменяемы: рейтинг может существовать без письменных отзывов.

Запись реализована собственной формой на `/book`: сервер получает услуги, мастеров, даты и сеансы, проверяет выбранный визит через `book_check` и создаёт его через `book_record`. Пользовательский токен для этих методов не используется. Успех подтверждается только полученным `record_id`. Защита от дублей хранится в `BOOKING_STATE_DIR`; требования к постоянному общему диску описаны в README. Реальная пробная запись в рабочем филиале не создавалась; серверный контракт проверяется на локальном макете API.

Источник: [официальная документация YCLIENTS](https://developers.yclients.com/), разделы «Авторизация запросов API», «Получить список сотрудников доступных для бронирования» и «Получить комментарии».
