# Подключение входа через Яндекс ID

Вход и личный кабинет используют серверные ключи Яндекс ID. В этой локальной копии ключи приложения добавлены в `.env.local`; этот файл исключён из Git. После клонирования или на рабочем сервере ключи нужно задать отдельно. Если ключей нет, сайт сообщает о недоступности входа и сохраняет запись без аккаунта.

## 1. Создать приложение

Откройте [Яндекс OAuth](https://oauth.yandex.ru/) под аккаунтом владельца барбершопа и создайте приложение для авторизации пользователей. Название: **SHERLOCK**. Платформа: **Веб-сервисы**.

Добавьте точные Redirect URI:

```text
http://localhost:3000/api/auth/yandex/callback
https://sherlock-murino.ru/api/auth/yandex/callback
```

Второй адрес замените, если рабочий домен будет другим. Протокол, домен, порт и путь должны совпадать с настройками сайта. Для локальной проверки открывайте именно `http://localhost:3000`, а не `127.0.0.1`.

Выберите права API Яндекс ID:

- `login:info` — имя и основные данные аккаунта;
- `login:email` — электронная почта;
- `login:default_phone` — телефон. Сайт запрашивает его как необязательное право; при отказе телефон можно вписать в профиле.

Укажите адрес сайта, описание и ссылку на политику `https://sherlock-murino.ru/privacy`, если кабинет запрашивает эти данные. Завершите предусмотренную Яндексом проверку приложения; до этого доступ может ограничиваться владельцем/тестовыми пользователями.

## 2. Добавить ключи на сервер

В `.env.local` уже предусмотрены поля:

```dotenv
YANDEX_CLIENT_ID=ClientID_из_кабинета
YANDEX_CLIENT_SECRET=Client_secret_из_кабинета
YANDEX_REDIRECT_URI=http://localhost:3000/api/auth/yandex/callback
ACCOUNT_DB_PATH=./.account-data/accounts.sqlite
AUTH_TRUST_PROXY=0
```

Client secret не публикуйте в исходниках и не добавляйте префикс `NEXT_PUBLIC_`. После изменения переменных перезапустите сервер. Для готовой сборки: `npm run build`, затем `npm run start`.

На рабочем сервере задайте HTTPS Redirect URI. Храните SQLite и её WAL-файлы на постоянном локальном диске сервера, вне `public`, и включите резервное копирование. Текущая реализация рассчитана на один сервер приложения с локальной SQLite. Для нескольких серверов или serverless требуется общая серверная БД. Доступ к файлам профилей ограничьте учётной записью сервера.

`AUTH_TRUST_PROXY=1` включайте только за доверенным прокси, который заменяет входной `X-Forwarded-For`. Без этого вход ограничивается общим лимитом 60 стартов за 15 минут на сервер; с доверенным прокси лимит применяется по IP.

## 3. Проверить вход

Запустите сайт (`npm run dev` либо `npm run build` и `npm run start`), затем выполните `npm run check:yandex`. Команда читает `.env.local` и проверяет начало входа на адресе из `YANDEX_REDIRECT_URI`: переход к Яндексу, ClientID, callback, PKCE, state и защищённую cookie. Секрет и cookie не выводятся. Проверка не авторизует пользователя и не подтверждает настройки приложения в кабинете Яндекса — для этого завершите вход в браузере.

1. Откройте `/account` и нажмите «Войти с Яндекс ID».
2. Разрешите передачу данных в Яндексе. После возврата откроется кабинет.
3. Проверьте имя и контакты, затем откройте `/book`: они должны подставиться в форму.
4. Нажмите «Выйти»: доступ к профилю должен закрыться.

Реальную запись для проверки входа создавать не требуется. История показывает только подтверждённые записи, созданные на этом сайте из текущего аккаунта; старые записи YCLIENTS автоматически по телефону не подгружаются. Отмена или перенос по телефону не обновляют статус истории автоматически.

## Проверки разработчика

```sh
npm run typecheck
npm run lint
npm run check:yandex
npx playwright test tests/account-server.spec.ts tests/booking-server.spec.ts
npm run test:accounts
```

OAuth-тесты используют локальный макет Яндекса. Проверки кабинета запускают отдельный сервер на порту 3101 и отдельную SQLite в `artifacts/`. Реальные аккаунты и записи они не изменяют. Тестовые адреса провайдеров игнорируются в production.

Вход использует Authorization Code + PKCE S256, одноразовый `state`, привязку к браузеру и серверный обмен кода. OAuth-токены Яндекса не отправляются браузеру и не сохраняются в профиле. Сессия сайта действует до 14 дней и хранится в HttpOnly cookie; на HTTPS включён Secure.

Источники: [регистрация приложения](https://yandex.ru/dev/id/doc/ru/register-client), [Authorization Code и PKCE](https://yandex.ru/dev/id/doc/ru/codes/code-url), [данные профиля](https://yandex.ru/dev/id/doc/ru/user-information).
