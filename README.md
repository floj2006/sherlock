# SHERLOCK

Сайт барбершопа в Мурино. Next.js 16.3.5, React 19, TypeScript, Tailwind CSS 4.

## Локальный запуск

Рекомендуется Node.js 22. Локально установленный Node.js 20.18 ниже требований части инструментов; для воспроизводимых проверок используйте версию из .nvmrc.

```sh
npm ci
npm run dev
```

Сайт: http://localhost:3000. Для серверных настроек скопируйте .env.example в .env.local и заполните только нужные параметры. .env.local исключён из Git. Ключи никогда не должны иметь префикс NEXT_PUBLIC_.

## Проверки

```sh
npm run lint
npm run build
npm run typecheck
npx playwright install chromium
npm run test:e2e
npm run test:accounts
npm audit
```

Playwright запускает проверки на компьютере и в мобильном Chromium. При необходимости задайте PLAYWRIGHT_EXECUTABLE_PATH для уже установленного браузера. Браузерные тесты используют ответы тестового API. Серверные проверки отправляют запросы в локальный макет YCLIENTS: реальные записи и уведомления не создаются. Снимки находятся в artifacts/, результаты ошибок — в test-results/. Эти каталоги исключены из Git.

## Контент

Услуги, цены, контакты и карточки мастеров находятся в src/lib/site-data.ts. Расширенные тексты мастеров — в src/lib/master-copy.ts. Фотографии — в public/. Административная CMS пока не подключена. Сверяйте цену и ID услуги с системой записи при изменениях.

Неподтверждённые резервные отзывы не публикуются: для проверенного редакционного отзыва требуется verified: true. Статические рейтинги скрыты; рейтинг показывается при получении допустимых данных из API. Не проставляйте verified без проверки первоисточника.

## YCLIENTS

Запись оформляется на странице `/book` внутри сайта, без iframe и внешнего окна. Форма получает актуальные услуги, цены мастера, даты и слоты через серверный `/api/booking`. Перед созданием сервер повторно проверяет стоимость, доступность сотрудника и времени, затем вызывает `book_check` и `book_record`. Успех отображается только после получения `record_id`.

Услуги выбираются флажками по категориям: один визит может включать несколько услуг. В сводке показаны выбранные позиции, общая цена и длительность. При изменении набора мастер, дата и время сбрасываются. Все ID передаются в YCLIENTS через повторяющиеся `service_ids[]`, а при создании — одним массивом `appointments[0].services`. Защита от дублей не зависит от порядка выбора. Поддерживаются ссылки `/book?services=mens-cut,waxing`, повторяющийся параметр `service` и прежние ссылки на одну услугу.

## Рейтинг Яндекс Карт

Рейтинг барбершопа отображается числом и звёздами на первом экране и крупно в разделе отзывов. Сервер читает значение из SVG официального бейджа Яндекса `sprav/widget/rating-badge` и кеширует ответ на час; значение не зашито в код. Парсер находится в `src/lib/yandex-rating.ts`, ID организации и URL — в `src/lib/business-profile.ts`. Ключ API не нужен. При недоступности источника или изменении его формата вместо выдуманного числа показывается ссылка на Яндекс Карты. Рейтинги отдельных мастеров по-прежнему получает интеграция YCLIENTS.

## Настройки YCLIENTS

- `YCLIENTS_COMPANY_ID` — ID филиала.
- `YCLIENTS_PARTNER_TOKEN` — серверный токен для онлайн-записи и рейтингов.
- `YCLIENTS_USER_TOKEN` — нужен только для текстов отзывов, если у пользователя есть доступ к филиалу.
- `BOOKING_STATE_DIR` — каталог устойчивого хранения подтверждений и защиты от дублей, по умолчанию `.booking-state`.

При развёртывании задайте `BOOKING_STATE_DIR` на постоянном диске, общем для всех экземпляров сервера. Обычная файловая система serverless-функции для этого не подходит: потребуется подключить общее хранилище или перенести реализацию `booking-store.ts` в транзакционную БД. Если каталог недоступен для записи, сервер не отправляет запрос создания визита. Не удаляйте ожидающие подтверждения записи из хранилища без проверки результата в YCLIENTS.

Сетевой сбой после отправки не приводит к автоматическому повторному созданию. Повтор того же визита возвращает сохранённое подтверждение либо неопределённый статус с предложением позвонить. Слоты и цены не кешируются. Лимит POST действует в пределах процесса; на публичном хостинге настройте общий лимит на доверенном прокси. Приложение принимает JSON только с собственного origin.

Текущий филиал не требует SMS-подтверждения телефона. Форма поддерживает услуги с оплатой в барбершопе. Если филиал включит обязательное SMS или предоплату, потребуется добавить соответствующий этап. Документация подключения — `YCLIENTS_CONNECT.md`.

## Личный кабинет

`/account` поддерживает вход через Яндекс ID, редактирование контактов, историю записей с сайта и повторный выбор услуг. Данные профиля подставляются в форму записи. Гости могут записываться без входа. Настройка приложения, Redirect URI и серверных ключей описана в [YANDEX_ID_SETUP.md](./YANDEX_ID_SETUP.md). SQLite находится вне публичной директории и требует постоянного диска. В production тестовые OAuth-адреса не используются.

При подтверждении записи из аккаунта к сохранённому подтверждению добавляются владелец и сведения об услугах. История привязывается к исходному владельцу даже при повторном запросе из другого аккаунта. Совпадение телефона или почты не объединяет пользователей.

## Аналитика и эксплуатация

Счётчики включаются настройками NEXT_PUBLIC_GA_ID / NEXT_PUBLIC_YM_ID и загружаются только после разрешения посетителя. Выбор можно изменить в подвале. Событие `book_click` фиксирует нажатие кнопки, `booking_complete` отправляется только после подтверждённого создания визита. Контакты гостя в аналитику не передаются.

GET /api/health проверяет работу приложения, а не YCLIENTS. Серверные ошибки регистрируются через src/instrumentation.ts без заголовков запросов и ключей. Уведомления об ошибках и контроль доступности нужно настроить на выбранном хостинге.

Перед публичным запуском см. LAUNCH.md.
